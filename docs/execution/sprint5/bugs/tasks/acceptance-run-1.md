R7 (BE; FE only if a label needs it) - the "altered or synthetic content" flag ignores AI narration
Reported: `deriveContainsSyntheticMedia` (`studio/src/run-pipeline/state-machine.ts`, about line 2002) is true only when `plan.visualSource === 'ai-stills'`, so a video with stock footage and AI narration is uploaded as not altered or synthetic. Founder decision (29 Oct): true when the pictures OR the narration are AI. Keep it a setting (Gate 2 and channel settings), default Yes. No channel name in code. Step one: check YouTube's current wording and put in the report what you read, on what date, and what you could not verify. The task writer's check on 29 Oct, read through a summarising fetch (not verbatim, so re-read the pages): (a) the Help page "Disclosing use of altered or synthetic content" requires disclosure of realistic AI-generated or meaningfully AI-altered content (a real person made to say or do something they did not, altered real footage, a realistic scene that did not happen, music as the main focus). It exempts clearly unrealistic or animated content and AI used as production help (scripts, captions, ideas). It does not list AI narration as a case of its own. It says disclosure alone does not limit audience or monetization, and that repeated non-disclosure can lead to penalties. It showed no last-updated date. (b) YouTube's March 2024 announcement names a generated voice narrating a video among its examples. (c) The API reference lists `status.containsSyntheticMedia` as settable on `videos.insert` but does not define it or its default. Not checked: the wording of the Studio upload dialog today. The founder's rule is stricter than YouTube's literal wording; that is intended (the safer side). Do not narrow it. Fix: narration counts as AI when a speech model produced it (every voice 7AI generates). Read the narration source from the plan or the run's voice config; if it is missing or unknown, count it as AI (fail toward disclosure). Pictures count as AI for `ai-stills` and for any other generative visual source the code has (check). One function owns the decision; every caller uses it. The setting: find out how it exists today (Gate 2, channel settings, profile) and how it interacts with the derived value: which one wins, and what the default is. Report that before changing anything. The default must read Yes. If no such setting exists today, stop and tell the founder (a new setting is a feature, not a hot-fix). Change the precedence no more than the decision needs. Sweep: every place AI-ness is derived from `visualSource` alone or hard-coded: the upload flag, the description's disclosure text, the pinned comment, the in-video tag, the Gate 2 and channel-settings labels, test fixtures. List the doc hits for the architect (the NIYT config "Studio defaults" line, the Part 3 design doc line that says the flag derives from `ai-stills`, Sprint 6 Task 2 R0 and R1). Coordination: Sprint 6 Task 2 (not started) reads this derivation in its R0 and R1 and must not change it; this item owns the change. List in the report what that agent must know. Tests: AI pictures with AI narration; stock pictures with AI narration (the new case, true); AI pictures with unknown narration; stock pictures with unknown narration (true); a path with no AI at all only if one exists (say if none does); the `videos.insert` body carries the right value; the setting reads Yes by default. Real check: the shared test Short (see Spend) uses stock-footage pictures with AI narration, so the old code would have sent No. Read the `publishing` stage output (it records what was sent), then the founder opens the Private video in YouTube Studio and confirms the altered-content setting reads Yes.
