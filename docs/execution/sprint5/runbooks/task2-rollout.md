## Preparation evidence required

Run the pinned `studio/scripts/prepare-publishing-rollout.mjs` from the existing `/var/www/7AI/studio` checkout as root, without checking out the PR or running application startup. The script can be copied to a private temporary file with `git show` after fetching the PR; fetching does not deploy or switch the checkout. The owner-facing command block pins the exact reviewed commit.

It reads the deployed `.env` and existing PM2 environment in memory. Its JSON output contains no credentials, raw PM2/config output, private content, provider session URIs or encrypted payloads. It checks that the effective existing AES-GCM key decodes to 32 bytes, agrees with the retained `.env` key, passes an in-memory round trip and decrypts every existing supported credential. It does not generate or rotate a server key. A zero-row credential count verifies availability/format, not historical ciphertext compatibility.

It creates a private custom-format `pg_dump` under `/var/lib/7ai/backups/pr92-*`, checks the archive table-of-contents and SHA-256, restores the entire archive into a new, uniquely named **`sevenai_pr92_verify_*_test`** database, and reads critical row counts there. The source must be local `sevenai_preview`. It never restores into the source, drops a database or changes application/schema configuration. The archive, checksum, verification marker and isolated restored DB are retained. Directory/file permissions are 700/600; the archive contains sensitive data and must stay private. This same-host copy is a tested rollback artifact, not a claim of off-host disaster recovery or a runtime-media backup.

It reports before/after running runs and possible active publishing stages, known-ID presence and legacy ambiguity; single-fork PM2 and other app PID inventory; root/deploy cron references; app/PM2 service names; sanitized operation order/hash from the actual `deploy.sh`; and Nginx vhost paths/maintenance-rule observations. A running row is possible active work, not proof of a live provider request. An old lease expiring never establishes that an upload stopped. A plain `pm2 restart` is not a drain.

Readiness requires successful backup restore/key checks and review of the real worker/deploy inventory against the handoff below. Script exit 0 alone does not authorize a deployment or claim the handoff was executed. Any failed section or unexpected process/scheduler keeps #92 draft until resolved.

## Recovery rules

- Before new workers start, a failed migration/build leaves the ingress gate closed and the old worker stopped. Investigate without starting upload-capable code. The nullable column may stay in place; do not discard receipts to make old code run.
- After any new publishing worker has run, **do not roll back to the pre-#92 publisher**: it ignores the receipt and can duplicate an insertion. Keep admission gated, preserve the receipt/session/first known ID and existing encryption key, and prefer a forward fix or an explicitly reviewed version that retains the receipt guard.
- Use a persisted known ID from any attempt; never insert again to repair R2, thumbnails or captions. Fixed-key R2 copy can be retried through the guarded implementation; uncertain thumbnail/caption effects stay uncertain and are not blindly repeated.
- An interrupted owner can reconcile only its same encrypted resumable session through the guarded implementation after separately authorized recovery. An expired/missing/unqueryable session after possible bytes remains ambiguous and blocks a fresh insertion. No title search, forced receipt rewrite, budget change or manual retry is part of these preparation checks.
- A database restore is an operator-approved recovery action, **not** an automatic rollback command. Reconcile all external uploads and writes after the chosen snapshot first; restoring an older DB can erase known IDs and create duplicate risk. Validate the archive checksum and restore into another isolated database first, preserving the current DB and receipt evidence. Never point the supplied restore-check command at `sevenai_preview`.
