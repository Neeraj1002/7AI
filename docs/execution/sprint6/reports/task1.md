## 2. Contracts I intend to build (for the architect to see now)

- **New stage `packaging`** (no migration): runs after `video_review` passes, before `gate2`. Output JSON: `{ scriptHash, brief, packages[3], kept[2], rendered[2] { id, device, title, question, answeredAt, recipe, files { full, feed, sidebar }, r2Keys? }, weakGap?, costUsd }`. Keyed by a hash of the sanctioned script, so a Gate 2 Revise (same script, new video) reuses the paid images instead of paying twice.
- **New LLM purposes** in the registry: `curiosity-brief` (R1) and `curiosity-packages` (R2, includes the text-only cold-reader ranking). Model and limits are chosen when I build them, evidence recorded as for every purpose.
- **Choice**: `runs.choosePackage { runId, packageId | 'youtube-suggested', editedTitle? }`, written to the `packaging` stage output **before** `runs.gate2 approve`; an edited title re-runs `checkMetadataClaims` and is refused if unsupported. Publishing reads the chosen title and file; when the choice is YouTube's suggested thumbnail, nothing custom is uploaded.
- **Files**: `GET /runs/:id/thumbnail/:packageId/:size` with a tenant check.
- **Publishing (R6)**: the existing isolated follow-up uploads the chosen file instead of the frame grab; a refusal leaves the video published, `coverFrameSet` false, the file kept, and the real reason in `coverFrameMessage`. The 403 itself is not investigated.
- **Profile**: optional `packaging.thumbnail` (font key, corner mark text, face policy) in `channel-profile/schema.ts`; absent means the neutral fallback face (Montserrat).
